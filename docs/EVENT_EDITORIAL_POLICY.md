# 事件编辑规则 v1

事件是一个可以被证据验证的现实状态变化，不是相似消息的文件夹。事件准入、重要性和
可信度相互独立：低重要性的普通 LPL 常规赛结果仍可形成事件；低可信度的单源转会爆料
也可立即形成未确认事件。

## 事件准入

- 普通 LPL 常规赛按中国时区比赛日形成 `match` 事件，稳定键为
  `matchday:lpl:YYYY-MM-DD`。同一天的赛程预告、进行中、赛果和赛后内容属于同一事件。
  普通常规赛重要性通常为 `0.55-0.68`；LPL 高于 LCK，知名队伍、明星选手以及明确影响
  排名、晋级或淘汰时提高。
- 季后赛后程的半决赛、胜者组决赛、败者组决赛和总决赛，在能够确定对阵双方时可按单场
  系列赛形成事件。`scheduled -> live -> completed` 是生命周期变化，不是拆分事件的依据。
- 明确包含选手或教练、转会动作和目标战队的单源爆料形成 `transfer` 事件，初始
  `lifecycle_status=unconfirmed`。模糊的“大动作”暗示不形成事件。
- 版本预览、完整预览、上线和热修复优先进入同一个 `patch` 主事件。
- 新英雄、英雄重做和核心玩法系统可形成 `major_gameplay_change` 事件。一条消息可以作为
  primary、component 或 cross_ref 同时进入多个事件。
- 互动、二创、泛宣传、纯观点和没有新事实的重复转载不创建新事件。

事件身份优先于时间窗口。游戏模式使用规范实体生成稳定键，例如
`mode:classic-mode`；“新模式”“游戏模式”“玩法模式”归一为同一分类。重大玩法和
游戏模式候选使用 180 天窗口，并以绝对发布时间差判断，因此离线批量数据按正序或倒序
处理都应命中同一事件。

候选检索采用两阶段召回：

- `strong`：稳定键、RawItem 版本链、核心实体或标题明确命中。
- `broad`：没有精确身份信号，但处于该事件类型的合理时间范围内。宽候选携带事件标题、
  摘要和核心实体，交由事件编辑判断别名、缩写、旧译名、父子对象和附属内容关系。

单条分析遇到礼包、皮肤、图标、封面、奖励、截图和测试服资源等附属对象时，必须同时
提取文本明确指向的父级模式、英雄、赛事、版本或活动。候选存在时如果仍选择 `create`，
必须通过 `candidate_rejections` 逐一说明为何每个候选都不是同一事件，否则草稿校验失败
并自动重试。附属素材没有改变核心事件状态时使用 `context`，不增加 revision。

### 国服神话商城轮换

- 国服神话商城的每周轮换形成一个低重要性 `shop_rotation` 小事件，稳定键按中国时区
  ISO 年与周生成，例如 `mythic_shop:cn:2026-W30`。
- 同一周的每日轮换加入该周事件，使用 `update_kind=context`，不增加 revision。
- 每日 context 不参与事件重要性；周更新按合格重大更新消息的最高重要性计算。
- 百度贴吧、微博和腾讯国服来源默认视为国服；文本明确写明国服也可判为国服。
- X/Twitter 来源的神话商城轮换按国际服处理，不得加入国服周事件，也不单独进入本站的
  事件层，使用 `not_event`。
- 周消息与每日消息无论处理顺序如何，都使用同一个周稳定键。标题中的“每周/每日”优先
  于正文中的附带描述判断轮换节奏。

## 事件更新

`update_kind` 区分：

- `new_fact`、`confirmation`、`refutation`、`correction`：构成显著更新并增加 revision。
- `context`、`duplicate_evidence`：可以补充证据和改变可信度，但不增加 revision，也不
  改写最新进展。

证据使用 `supports`、`contradicts`、`context` 三种立场。

### 同一来源文档的版本链

`RawItem.supersedes_raw_item_id` 表示同一来源文档的新采集版本，不表示新的消息或独立
来源：

- 消息列表和事件处理台只展示版本链中没有 successor 的最新版本。
- 已被取代的 NormalizedItem 不允许启动或批准事件聚合。
- 新版替代已经属于事件的旧版时，原位替换 `event_messages` 成员，不追加第二条证据。
- 页面修订没有实质新事实时使用 `duplicate_evidence`，不增加事件 revision；确有新增
  事实时才生成新的事件 revision。
- 旧 RawItem 和旧 NormalizedItem 保留用于审计，不从数据库删除。

## 可信度

证据先按 `independence_key` 去重。原创使用 `source:{source_id}`；转载使用规范化的
`upstream:{host}{path}`；无法识别上游的转载不参与加成。同一账号或同一上游只贡献一次。

非官方仅有支持证据时：

```text
base = max(independent supporting source reliability snapshot)
boost = 0.1 × min(independent supporting source count - 1, 3)
credibility = min(0.9, base + boost)
```

只有原始官方来源直接确认其权责范围内的核心事实，并经事件审核确认后，
`is_official_evidence` 才为真。该值由程序根据 `Source.is_official`、是否直接原创和证据立场计算；官方转发不算直接确认。官方支持将事件标为
`official_confirmed` 且可信度为 `1.0`；官方否认将核心主张标为 `officially_refuted`。
官方支持与反对同时存在、或非官方支持与反对同时存在时均为 `disputed`、可信度 `0.5`。

## 重要性

消息重要性使用 `importance-v3-editorial-baselines`：模型只提取编辑子类型、规模、赛区、
对象知名度、首次具体披露和重复提醒等特征，程序按版本化基准分、有限修正项和子类型区间
确定性计算。紧迫性与可信度均不进入重要性分。

- 神话商城普通每日轮换约 `0.50`；皮肤/炫彩约 `0.60`；稀有炫彩和版本级批量上新
  可提高到 `0.60-0.70`。仅外服且不影响国服的轮换减 `0.20`；外服轮换不进入国服事件。
- 普通版本预览约 `0.84-0.90`；完整预览、正式完整更新内容为 `0.87-0.95`；
  单英雄或小范围热修复按影响程度为 `0.70-0.85`。
- 新英雄、新模式和重大玩法更新保留独立编辑子类型，但与完整版本内容使用相近的
  `0.87-0.95` 区间；这样可以独立解释和归类，而不会因为同时属于版本更新重复加分。
- 新皮肤按档次为 `0.68-0.80`：普通皮肤靠近下限，传说、至臻/神话和终极皮肤依次提高。
- 普通活动为 `0.70-0.85`；以付费为主的活动通常为 `0.70-0.80`；明确可免费获得皮肤的
  活动为 `0.86-0.94`。
- 拳头公司与世界观内容通常为 `0.60-0.70`。
- 常规赛为 `0.55-0.68`，季后赛和赛区决赛为 `0.68-0.76`，世界赛普通场次为
  `0.60-0.70`，焦点或关键场次为 `0.70-0.80`。
- 转会和阵容消息通常为 `0.55-0.65`，明星选手相关可提高到约 `0.70`。
- 活动、版本、皮肤、服务等内容如果明确只影响外服且不影响国服，按类型减
  `0.12-0.20`；国服与全球同步内容不减。赛事、转会、公司和世界观内容不使用服务器扣分。

事件重要性不累加成员消息数量，也不因官方身份或独立信源数量加分。先取所有合格活动
成员中 `is_significant_update=true` 的消息重要性最高值；没有重大更新时回退到其他合格
成员的最高值。`context` 与 `duplicate_evidence` 不参与。

公开卡片展示事件类型、生命周期、重要性、可信状态、独立来源数、证据数和最新进展；
内部 `event_key` 与 revision 历史保留在详情审计区。
